1. WHAT THIS IS
---------------
An offline profiler for LLM context windows. It samples real requests, ablates segments
(system-prompt sections, tool schemas, retrieved chunks, prior turns), scores how much the answer
changes, fits a sparse linear surrogate (Lasso, the ContextCite method, NeurIPS 2024), aggregates
across hundreds of traces, and ranks segments by tokens paid × influence. The output is meant to
be a pull request: "these segments had ~zero influence across N traces; removing them cuts input
tokens by X%; your eval still passes." X must be measured, never a target.

Interview line: "I built a profiler that tells you which parts of a prompt you're paying for but
not using, and proves removing them is safe."

Spec source: section 3 of "Project Ideas Lab — 10 Build Specs for Dior.docx" (Downloads).
Non-goal: no real-time production proxy.

3. ARCHITECTURE AND FILE MAP
----------------------------
Python 3.12 package `ctxprof` (src layout), Typer CLI, FastAPI, SQLite, scikit-learn, numpy.
Frontend: React 18 + Vite 6 + TypeScript 5.6, no UI libraries.

  src/ctxprof/
    models.py        Pydantic models: Message, Tool, Request, Response, Trace, Segment, Locator, Span.
                     A Locator says how to remove a segment: tool index | whole message | char spans.
    tokens.py        TokenCounter protocol. HeuristicCounter (default, deterministic, no deps) and
                     TiktokenCounter (optional extra: pip install -e ".[tiktoken]").
    segmenter.py     SegmenterConfig (YAML) + segment_trace(). Rules: each tool = segment; docs carved
                     out of any message by regex; system messages split by markdown headings; last user
                     message = user/current; earlier messages = history/<role> -<distance>.
                     fingerprint_rewrites (regex) merge per-request ids, e.g. rag/listing:* .
    masking.py       sample_masks() (guarantees each segment is kept and dropped at least once) and
                     apply_mask() (removes spans/messages/tools, repairs tool_call/tool_result pairs).
    importers/       jsonl.py (OpenAI and Anthropic shapes) and otel_genai.py. ALL OpenTelemetry GenAI
                     attribute names live in otel_genai.MAPPING because the conventions are still in
                     development status: change only that table when they move.
    providers/       base.py (async Provider: generate, optional target_logprob),
                     fake.py (FakeProvider: deterministic ground-truth model built from Effects),
                     openai_compat.py (any OpenAI-compatible chat endpoint; black-box mode only).
    scoring.py       logprob -> logit score; black-box metrics: char-3-gram cosine text similarity,
                     tool-call agreement, JSON field agreement, "auto".
    surrogate.py     fit_surrogate(): LassoCV (alpha by CV) on a train split -> held-out R²; refit on
                     all masks; bootstrap 95% CIs. normalise(): influence = weight / max(top weight,
                     min_effect), clipped to [-1, 1].
    attribution.py   ProfileConfig, CallGate (cache + hard budget + semaphore), profile_trace(),
                     run_profile(). Pins the current user turn (see decision D1).
    aggregate.py     aggregate() per fingerprint: traces, tokens mean/paid, mean/sd/p95 influence,
                     influence per 1k tokens, label. injection_signals(). LabelRules holds thresholds.
    flame.py         flame_tree(): request -> kind -> segment, with token offsets for the ruler.
    storage.py       SQLite schema: traces, segments, runs, trace_fits, attributions (NULL weight =
                     pinned), ablations, calls (the cache). Store class.
    server.py        FastAPI: /api/health, /api/runs, /api/traces, /api/traces/{id},
                     /api/traces/{id}/flame, /api/runs/{id}/aggregate. Serves web/dist at /.
    cli.py           ctxprof import | profile | aggregate | flame | prune* | verify* | serve | demo
                     (* = M4 stubs that exit with code 2).
    demo.py          The bloated JobBridge support agent: ~2,000-token system prompt (9 sections),
                     12 tools, KB + employer listings (some with an injected "registration fee"),
                     200 traces in English and Sheng, and demo_effects() = the ground truth.
  tests/             test_segmenter, test_masking, test_importers, test_attribution (synthetic ground
                     truth, cache, budget, black-box, labels, injection), test_server.
  web/src/
    styles.css       Graticule design tokens (dark default, light via prefers-color-scheme or
                     <html data-theme="light|dark">), all component CSS, reduced-motion fallback.
    components/Flame.tsx   The signature flame graph (see section 6).
    views/Overview.tsx     Run summary, DEAD list, top influence/1k, injection signals, trace list.
    views/Segments.tsx     Aggregated table, sortable (tokens paid / mean / per 1k), kind/label filters.
    views/TraceView.tsx    Flame + selected rail + drill-down (ablation raster, original response,
                           surrogate weights with CI).
    api.ts / heat.ts / hooks.ts   Typed API client, influence->heat bins, a tiny loader hook.
  examples/demo/     Generated by `ctxprof demo` (git-ignored): traces.jsonl, segmenter.yaml,
                     prompt/system.md, prompt/tools.json (the prompt bundle M4 will diff).
  ctxprof.db         Generated SQLite DB (git-ignored).


4. KEY DECISIONS (and why — keep them unless you have a reason)
---------------------------------------------------------------
D1 Pin the current user turn (ProfileConfig.pin_kinds = ("user",)). The question is not context
   (ContextCite attributes to context sources). Ablating it made every other effect conditional
   on it (an AND), which a linear surrogate cannot fit: a dead section got weight 0.36 in testing.
   Pinned segments are stored with NULL weight and shown as "not scored" (hatched) in the UI.
D2 Influence = weight / max(strongest positive weight, min_effect). Comparable across traces and
   0..1 for heat. The floor (0.5 nats logprob, 0.05 black-box) stops traces where nothing matters
   from inflating noise to 1. Raw weights are stored too.
D3 Labels: CRITICAL if mean >= 0.5; else VOLATILE if sd >= 0.15; else DEAD if >= 20 traces,
   |mean| < 0.05 and p95(|influence|) < 0.10. VOLATILE is never auto-pruned. Thresholds live in
   LabelRules; the spec's "M traces" is min_traces.
D4 Poor fit = held-out R² < 0.5; such traces are excluded from aggregation and counted in the UI.
D5 Every model call is cached by sha256(kind, provider, model, params, masked request, target).
   Re-runs are free and reproducible. Cache inserts commit with the trace's results (fast).
D6 Budget is a hard cap checked BEFORE each uncached call using a token-count estimate; a run that
   hits it stops cleanly with status "budget" and keeps finished traces.
D7 Temperature is forced to 0 on replays (force_temperature_zero).
D8 Heuristic token counter by default for determinism; use --counter tiktoken for real numbers.
D9 Fake model (FakeProvider + Effects) is the ground truth: an effect fires only if its gate words
   are in the user question and its "needs" substrings are in the request; it adds weight nats to
   the original answer's log-probability. A correct method must recover exactly those segments.
D10 Colour means influence only. Status (DEAD/CRITICAL/VOLATILE/injection) is glyph + word.
    Removed diff lines (M4) must be hatched/struck, NOT red.

6. DESIGN SYSTEM ("Graticule")
------------------------------
Design canvas (Claude Design artifact, private): https://claude.ai/artifact/4YvZrWGN3bp9twR967EvAj

375 px board, system sheet. The web UI implements Overview, Flame, Segments and Trace so far.

Concept: a bench spectrum analyser for the context window: a token ruler on top, the flame stack,
M1/M2 delta markers, a detail rail.
  - Type: Archivo with its width axis (wdth 125 hero, 100 prose, 62–72 labels/wordmark) +
    Spline Sans Mono (tabular) for all data. Loaded from Google Fonts in web/index.html.
  - Palette: graphite chassis/bezel/well/graticule + one heat ramp H0..H6 used ONLY for influence.
      dark  H0..H6: #2c4d7d #366794 #49829f #7a9997 #dd9b5f #ffb45b #ffe183 (surface #14161a)
      light H0..H6: #86a6cf #6494c1 #4a84a1 #52706d #864100 #782200 #5b1001 (surface #e8e9ea)
    Bins (web/src/heat.ts): <.05, .05, .15, .25, .40, .55, >=.70.
  - Signature interaction: scroll zooms at the cursor through the window (ruler ticks re-step),
    Shift+scroll pans, W/A/S/D/F/0 on the focused stack, minimap brush, ruler drops M1/M2 and the
    readout sums tokens, influence and cost between them. A one-time "sweep" line develops the heat
    on load. All motion off under prefers-reduced-motion.

9. GLOSSARY
-----------
  segment      a removable piece of the request (section, tool, chunk, turn).
  fingerprint  stable id for a segment across traces, e.g. "system/## Tone rules", "tool/search_jobs",
               "rag/listing:*", "history/user -1".
  mask         one ablation: which segments are kept (True) or removed (False).
  weight       Lasso coefficient for a segment (score units: nats in logprob mode).
  influence    weight relative to the trace's strongest segment, clipped to [-1, 1].
  tokens paid  sum of a fingerprint's tokens over all traces that carried it.
  DEAD / CRITICAL / VOLATILE   aggregate labels (section 4, D3).
  injection signal   an untrusted, non-user segment in the top 10% of its trace with influence >= 0.3.
